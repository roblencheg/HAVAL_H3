# GWM RU: экспериментальная запись протокола

Доступно в ветке `feature/protocol-capture` (`1.0.13-capture.1`), **не в стабильном релизе**.

Инструмент записывает последовательность полученных облачных состояний автомобиля в JSONL, сопоставляет предыдущие и новые значения, поддерживает ручные метки и выгружает последние 500 записей текущей сессии через стандартную диагностику Home Assistant. Запись **по умолчанию выключена** и после перезагрузки HA автоматически не возобновляется. Управляющие команды в автомобиль не отправляются.

## Как провести исследование ACC без запуска двигателя

В **Инструменты разработчика → Действия** выполните последовательность:

1. `gwm_ru.protocol_capture_start` (без параметров, если настроен один аккаунт). Сразу запрашивается исходное состояние.
2. `gwm_ru.protocol_capture_marker` с `label: IGN_OFF`.
3. Не нажимая тормоз, штатной кнопкой Start включите зажигание без запуска двигателя.
4. `gwm_ru.protocol_capture_marker` с `label: IGN_ON`.
5. `gwm_ru.protocol_capture_refresh`. Дождитесь обновления данных GWM Cloud; отсутствие изменений может означать, что TBOX ещё не передал новое состояние.
6. Аналогично выключите зажигание, добавьте метку `IGN_OFF_AGAIN` и выполните `gwm_ru.protocol_capture_refresh`.
7. `gwm_ru.protocol_capture_stop`, затем **GWM RU → Скачать диагностику**. Ищите `protocol_capture.vehicles[].records` и `changes`.

Пример ручной метки:

```yaml
action: gwm_ru.protocol_capture_marker
data:
  label: IGN_ON
```

Если настроено несколько аккаунтов GWM RU, передавайте `entry_id` для выбора аккаунта. Для меток конкретного автомобиля можно передать `vin`, но **не вписывайте VIN в текст `label`**. Все автомобили аккаунта записываются раздельно; в диагностике их блоки идут в порядке автомобилей аккаунта без исходного VIN.

## Что записывается

- `getLastStatus.items`: числовые коды и короткие числовые значения, без координат и произвольных строк;
- разрешённые поля состояния двигателя, климата, замка и TBOX;
- только метаданные `acquisitionTime`, `updateTime`, `serviceStatus` и константа `STATUS`;
- только `powerGear` и `quickSettings` из `vehicleBasicsInfo.config`;
- timestamp, ручные метки, baseline и диффы между обновлениями.

Во время записи выполняется дополнительный **GET** `vehicleBasicsInfo` для каждого автомобиля при каждом штатном обновлении. Ни `T5/sendCmd`, ни POST-команды инструментом не вызываются. Запись не заставляет автомобиль передавать свежую телеметрию чаще: сервер может возвращать кэш.

Файлы сохраняются локально в `/config/.storage/gwm_ru_capture_*.jsonl` с хешированным VIN в имени. Они **не удаляются автоматически**: при необходимости удаляйте их вручную после остановки записи, учитывайте при резервном копировании и не публикуйте оригинальные файлы без проверки. В диагностику включаются только baseline и последние 500 записей последней сессии. Метка вводится пользователем и не должна содержать персональных данных.

## Ограничения

Наличие изменившегося кода не доказывает, что он управляет зажиганием. Требуется повторный эксперимент с OFF/ACC/ON и контрольными состояниями. Сервис `protocol_capture_refresh` только читает облако; удалённую команду ACC он не создаёт. Для функции в production необходимы отдельная проверка на H3, кодовая ревизия и подтверждение совместимости.
