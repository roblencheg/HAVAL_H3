# GWM RU: экспериментальная запись протокола

Доступно в ветке `feature/protocol-capture`, начиная с prerelease `v1.0.13-capture.2`. Стабильный релиз не изменяется. Запись включается вручную и не возобновляется после перезагрузки Home Assistant. Управляющих команд автомобиль не получает.

## Исследование OFF / ACC / ON без запуска двигателя

В **Инструменты разработчика → Действия**:

1. Выполните `gwm_ru.protocol_capture_start`: создаётся исходный снимок.
2. Добавьте метку через `gwm_ru.protocol_capture_marker`, `label: IGN_OFF`. Затем выполните `gwm_ru.protocol_capture_refresh`.
3. Нажмите Start без педали тормоза, включив штатный режим ACC/зажигания без запуска двигателя. Добавьте `label: IGN_ACC` и выполните `gwm_ru.protocol_capture_refresh`.
4. Если автомобиль штатно позволяет перейти в следующий режим ON без двигателя, отметьте его отдельно `label: IGN_ON` и снова обновите. Не запускайте двигатель ради этого теста.
5. Выключите зажигание, добавьте `label: IGN_OFF_AGAIN`, затем выполните `gwm_ru.protocol_capture_refresh` дважды с интервалом 20–30 секунд.
6. Вызовите `gwm_ru.protocol_capture_stop` и скачайте стандартную диагностику GWM RU. Данные находятся в `protocol_capture.vehicles[].records`.

Пример:

```yaml
action: gwm_ru.protocol_capture_marker
data:
  label: IGN_ACC
```

Если GWM возвращает кэш, потребуется повторить чтение, пока не обновится `acquisitionTime`. Метка является наблюдением пользователя, а не подтверждённым облачным состоянием.

## Поля в capture.2

- `signals`: числовые коды GWM `getLastStatus.items` и короткие числовые значения;
- `state`: ограниченный набор уже известных состояний двигателя, замка, климата, TBOX;
- `status_meta`: `acquisitionTime`, `updateTime`, `serviceStatus` и значение `STATUS`;
- `vehicle_basics`: `powerGear`, `quickSettings`. `powerGear` — конфигурация, а не подтверждённый индикатор зажигания;
- `power_fields`: только если фактически присутствуют числовые `power`, `ignitionStatus`, `engineSts`, `drivingStatus`, `hutSwitchOn`, `gpsSwitchOn`, `hcuPowertrainSts`, `tboxStatus` на верхнем уровне либо в `vehicleStatusInfo`/`statusInfo`. Регистр имён не важен;
- `power_probe`: `ok` при успешном дополнительном GET, `request_failed` в случае ошибки. Пустой `power_fields` при `ok` означает, что подходящих числовых полей не обнаружено, а не что питание выключено;
- `freshness`: `baseline`, `fresh`, `cached_or_out_of_order` или `unknown`. Сравнение ведётся по `acquisitionTime`, а не по факту HTTP-ответа. Дифф `changes` рассчитывается только для свежих снимков. При кэшированном ответе предыдущий достоверный снимок сохраняется как опорный.

Имена кандидатов взяты из [moryoav/ha-gwm-ev](https://github.com/moryoav/ha-gwm-ev/blob/main/gwm_client/china_gtsp.py) и [chaosl1996/gwm_cn_ha](https://github.com/chaosl1996/gwm_cn_ha/blob/main/custom_components/gwm_cn/gwm_api.py). В китайской интеграции поле `vehicleStatusInfo.power` подписано: `0` питание выключено, `1` ACC, `2` ON, `3` READY. Это **не проверенная карта значений российского H3**. `vehicleBasicsInfo.config.powerGear` — другое поле, и при первом тесте оно оставалось равным `10`.

Во время записи при штатном обновлении интеграции выполняются дополнительные чтения `GET vehicleBasicsInfo` и `GET getLastStatus`. Никаких `T5/sendCmd`, `remote-ctrl/timely`, POST-управления, CAN и изменений конфигурации нет. Ответы полностью не сохраняются. Автомобиль может не отправить новое состояние в облако, даже если GET выполнен успешно.

Файлы сохраняются локально в `/config/.storage/gwm_ru_capture_*.jsonl` с хешем VIN в имени и не удаляются автоматически. В диагностике экспортируются baseline и последние 500 записей текущей сессии. Метки вводит пользователь: не помещайте в них VIN, адреса и личные данные. Для нескольких аккаунтов укажите `entry_id`, а для выбора машины допускается аргумент `vin` вне метки.

## Ограничения и результаты поиска удалённой команды

Ручное включение зажигания кнопкой без тормоза проверено владельцем H3; удалённый аналог этого действия пока не обнаружен. В публичных перечнях возможностей приложения GWM описаны удалённый запуск двигателя и климат, но отдельный ACC/IGN/HUT wake не заявлен. Изученные проекты реализуют `T5/sendCmd`, `remote-ctrl/timely` и другие региональные команды, однако подтверждённого отдельного действия ACC нет. Не отправляйте неописанные `controlType`/`remoteType` либо `allowStartEng=0` наугад. `allowStartEng=1` из китайской климатической команды прямо допускает запуск двигателя. До подтверждения на H3 все состояния питания остаются исследовательскими данными, а не функциональностью управления.
