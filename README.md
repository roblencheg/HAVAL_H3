# GWM RU for Home Assistant

Неофициальная интеграция для российского облака **GWM / HAVAL / TANK / ORA / WEY**: состояние автомобиля, удалённое управление и четыре встроенные карточки Dashboard.

Проверено на **Haval H3** через российское приложение GWM 2.3.1. Доступность функций на других автомобилях зависит от модели и данных облака.

[Релизы и история изменений](https://github.com/roblencheg/HAVAL_H3/releases) · [Сообщить о проблеме](https://github.com/roblencheg/HAVAL_H3/issues)

## Установка и подключение

[![Установить через HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=roblencheg&repository=HAVAL_H3&category=integration)

1. В **HACS → ⋮ → Custom repositories** добавьте `https://github.com/roblencheg/HAVAL_H3` с категорией **Integration**.
2. Установите **GWM RU** и полностью перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию → GWM RU**.
4. Введите телефон и пароль аккаунта GWM. Для команд укажите PIN из приложения и включите **«Включить удалённое управление»** в настройках интеграции.

При ручной установке скопируйте папку [custom_components/gwm_ru](custom_components/gwm_ru) в `/config/custom_components/gwm_ru`, затем выполните шаги 2–4.

> Рекомендуется отдельный аккаунт GWM с доступом через **«Поделиться автомобилем»**: одновременная работа приложения и Home Assistant под одним аккаунтом может приводить к выходу из него.

## Возможности

| Раздел | Мониторинг и управление |
| --- | --- |
| Двигатель и доступ | Состояние двигателя, запуск с заданным временем работы и остановка; замок, двери и багажник; блокировка/разблокировка, открытие/закрытие багажника |
| Окна и люк | Состояние окон и люка, закрытие |
| Климат и обогревы | Климат с температурой 16–32 °C; обогрев руля, лобового и заднего стекла; подогрев обоих передних сидений: выкл. / 1 / 2 / 3; состояние переднего дефроста |
| Топливо и пробег | Топливо в литрах и процентах, запас хода, общий пробег |
| Шины | Давление, температура и отдельные TPMS-предупреждения каждого колеса |
| Местоположение | GPS `device_tracker`, карта поездок, маршруты и стоянки |
| Связь и команды | TBOX онлайн, история и результат команд, принудительное обновление, фары и звуковой сигнал |

Функции определяются отдельно для каждого автомобиля по заявленным возможностям и доступной телеметрии. Для каждой машины аккаунта создаётся отдельное устройство. Сущности `sensor`, `binary_sensor`, `switch`, `select`, `climate` и `device_tracker` можно использовать в стандартных карточках и автоматизациях Home Assistant.

## Карточки Dashboard

Карточки входят в интеграцию. После перезапуска Home Assistant откройте **Редактировать панель → Добавить карточку → GWM RU**, выберите карточку и автомобиль.

| Карточка | Для чего |
| --- | --- |
| **GWM RU** | Состояние автомобиля, топливо, шины, управление и профили подготовки |
| **GWM RU — анимированный пульт** | Визуальное состояние автомобиля и быстрые команды |
| **GWM RU — анимированный пульт · горизонтальный** | Широкая версия пульта: автомобиль слева, команды справа, компактные сенсоры отдельным блоком |
| **GWM RU — Поездки** | Карта маршрутов, пробег, стоянки и интервалы без GPS за выбранный период |

У всех карточек есть визуальный редактор. Они используют устройства `gwm_ru` и не привязаны к конкретной модели; заголовок по умолчанию — **Haval**.

**Подготовка автомобиля** в основной карточке последовательно запускает двигатель, климат и подогрев сидений с выбранными параметрами. Настройки можно сохранять в локальные профили, например «Зима» и «Лето».

**Горизонтальный анимированный пульт** использует те же данные, команды, редактор и анимацию, что обычный пульт, но рассчитан на широкие секции Dashboard. Управляющие кнопки визуально отделены от пассивных сенсоров; сенсоры сделаны компактнее, чтобы карточка занимала меньше высоты.

**Поездки** автоматически находят GPS-сущность автомобиля; при необходимости её можно выбрать в редакторе. История точек хранится локально в Home Assistant, а Recorder при наличии используется для заполнения пропусков. Полнота маршрута зависит от поступающих GPS-данных.

В стандартном режиме Lovelace (storage) JavaScript-ресурс регистрируется автоматически — добавлять его вручную не нужно. Для YAML-режима предусмотрен отдельный механизм подключения через frontend.

<details>
<summary>Типы карточек для ручной YAML-конфигурации</summary>

Используйте один из типов:

- `custom:gwm-vehicle-card`
- `custom:gwm-vehicle-remote-card`
- `custom:gwm-vehicle-remote-horizontal-card`
- `custom:gwm-vehicle-trips-card`

Например:

```yaml
type: custom:gwm-vehicle-card
```

</details>

## Настройки

Доступны в настройках интеграции **GWM RU**.

| Параметр | Назначение / значение по умолчанию |
| --- | --- |
| Poll interval | Обновление данных: **300 секунд** |
| Включить удалённое управление | Разрешение отправлять команды автомобилю |
| Command cooldown | Пауза между командами: **5 секунд** |
| ПИН из приложения | Сохранение или удаление PIN для удалённых команд |

При ручном вызове действия без `vin` команда отправляется **первой машине аккаунта**. Для выбора другой передайте её VIN. Управляющие сущности и карточки используют выбранный автомобиль.

<details>
<summary>Примеры действий для автоматизаций</summary>

Запуск на 15 минут:

```yaml
action: gwm_ru.engine_start
data:
  operation_time: 15
  vin: "VIN_АВТОМОБИЛЯ"
```

Остановка:

```yaml
action: gwm_ru.engine_stop
data:
  vin: "VIN_АВТОМОБИЛЯ"
```

Температура климата — замените `entity_id` на сущность своей машины:

```yaml
action: climate.set_temperature
target:
  entity_id: climate.gwm_ru_klimat
data:
  temperature: 22
```

</details>

## Важно знать

- **Топливо в процентах** рассчитывается из объёма топлива и `tankCapacity`, полученных от GWM. Если ёмкость бака отсутствует, процент неизвестен.
- **«На охране»** означает закрытый центральный замок, а не отдельный сигнал штатной сигнализации. Остальные общие статусы: «Запущена», «Открыта», «Неизвестно».
- После подтверждённого удалённого запуска или остановки источник состояния двигателя обозначается как `remote_command_result`.
- Команды выполняются через облако и реально управляют автомобилем. Учитывайте это при создании автоматизаций запуска и разблокировки. Пароль и PIN хранятся в конфигурации Home Assistant.

## Если что-то не работает

**Карточка не появилась или возникла ошибка `Custom element doesn't exist`:** обновите интеграцию, полностью перезапустите Home Assistant и перезагрузите страницу Dashboard.

**Нет данных или недоступна команда:** проверьте доступность функции в приложении GWM, настройки удалённого управления и PIN. Отсутствие данных облака может ограничивать доступные сущности и действия.

**Для обращения об ошибке:** скачайте диагностику через **Настройки → Устройства и службы → GWM RU → Скачать диагностику** и приложите её к [issue](https://github.com/roblencheg/HAVAL_H3/issues) вместе с версией интеграции и описанием проблемы. Диагностика содержит телеметрию, возможности автомобиля и результат последней команды; чувствительные данные и идентификаторы скрываются.
